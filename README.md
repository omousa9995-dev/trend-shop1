## التشغيل والفحص

تعمل الاختبارات على Node.js 22 أو أحدث دون تنزيل تبعيات:

```bash
npm test
```

لمعاينة الواجهة ومحاكاة الطلب دون حفظ بيانات:

```bash
python3 -m http.server 8765 --directory public
```

افتح `http://localhost:8765`. تتطلب الإدارة Worker وD1 وKV. للتطوير الكامل في بيئة موثقة الصلاحية:

```bash
npm install
npx wrangler login
npm run db:local
npm run db:seed-local
npm run dev
```

ضع أسرار التطوير في `.dev.vars` المستبعد من المستودع. لا ترفع كلمات المرور أو رموز التفعيل.

## النشر الاعتيادي

يستخدم `wrangler.jsonc` إعداد Workers Assets للواجهة، وD1 للبيانات، وKV باسم `MEDIA` للصور المرفوعة. معرّفات الموارد تخص حساب المالك الحالي؛ أنشئ موارد أخرى وأبدل معرّفاتها إذا نقلت المشروع لحساب آخر.

للقاعدة الجديدة فقط:

```bash
npx wrangler d1 execute trend-shop-db --remote --file=db/schema.sql
npx wrangler d1 execute trend-shop-db --remote --file=db/seed.sql
```

لترقية قاعدة 1.2، طبّق `0002_product_details.sql` مرة واحدة قبل بيانات التشكيلة. **طُبقت هذه الترقية بالفعل على المعاينة الحالية؛ لا تكررها على القاعدة الحالية.**

للترقية إلى 1.4، تطبق `0003_initial_pricing_stock.sql` التسعير الفردي والمخزون المبدئي مرة واحدة، ويسجل التطبيق في `catalog_releases`. **طُبقت بالفعل على القاعدة الحالية.** إعادة الترقية أو `seed.sql` لا تعيد القطع المباعة إلى 24 ولا تستبدل الأسعار المعدلة لاحقًا. ما زال `seed.sql` يعيد الأسماء والأوصاف والصور وحالات العرض؛ لا تُعد تنفيذه بعد تحرير هذه الحقول دون مراجعة ونسخة احتياطية.

للنشر بالإعداد الحالي الفعّال:

```bash
npm run deploy
```

النسخة المنشورة تستخدم محول ملفات مضمّن يُبنى بواسطة `node scripts/prepare-api-preview.mjs`، والصور من KV. مخرجاته في `deployment-private/` المستبعد من التسليم. النشر الاعتيادي بـWrangler يخدم الصور المجمعة من `public/` مباشرة عبر Workers Assets، ويستخدم KV للصور الجديدة التي يرفعها المدير.

## الإدارة من الآيفون

افتح `/admin.html`. للتفعيل الأول أدخل الرمز الخاص الذي سُلّم للمالك واختر كلمة مرور من 14 حرفًا على الأقل. يُغلق التفعيل بعد إنشاء الحساب. لا يُحفظ نص كلمة المرور.

لتغيير صورة: افتح محرر المنتج، ثم «رفع صورة من الآيفون أو الجهاز»، واختر الصورة، وانتظر نجاح الرفع، ثم «حفظ التغييرات». يهيئ المتصفح الصورة إلى JPEG بأقصى ضلع 1600 بكسل، ويزيل بيانات EXIF. حد الخادم 1.5 MiB بعد التهيئة. إذا تعذر فتح صيغة من الجهاز، اختر نسخة JPEG أو PNG. يبقى إدخال رابط الصورة متاحًا.

الأوصاف والفوائد والاستخدام قابلة للتحرير من النموذج نفسه. الإخفاء والاستعادة يحفظان السجل وتاريخ الطلبات. صور العبوات مراجع بصرية؛ يُطابق الحجم والإصدار مع مخزون المورد قبل الاعتماد.

يتحقق الخادم من بقاء السعر النهائي بعد أي خصم بين 0.500 و20.000 دينار. الأسعار الحالية حُددت لكل منتج، وليست حسابًا لهامش الربح لعدم توفر تكلفة الشراء. الكميات مسجلة بناءً على توجيه المالك وليست جردًا ماديًا.

## الأسرار والبريد

`SESSION_SECRET` و`SETUP_TOKEN` موجودان كأسرار Worker؛ احتفظ بهما عند التحديث. يدعم الخادم تجزئة `ADMIN_PASSWORD_HASH` أو تجزئة المالك من D1 بعد التفعيل.

لربط البريد، يلزم تسجيل الدخول إلى حساب Google الخاص بالمتجر. ينشأ مشروع Apps Script بالمصدر `integrations/google-apps-script.gs` والبيان `integrations/appsscript.json`. بعد موافقة المالك على صلاحية الإرسال، تُشغّل `initializeMailBridge` من محرر المالك: تنشئ سرًا عشوائيًا في Script Properties باسم `TREND_WEBHOOK_TOKEN` إذا لم يكن موجودًا، وتحافظ عليه عند التكرار، وترسل اختبارًا إلى بريد المتجر فقط دون طباعة السر. تُشغّل `checkMailBridge` للفحص دون إرسال. يُنشر Web App يعمل باسم المالك؛ كل طلب إليه يجب أن يحمل السر. يُحفظ رابط النشر في سر Worker `MAIL_WEBHOOK_URL` والسر المطابق في `MAIL_WEBHOOK_TOKEN`. لا تُحفظ هذه القيم في المستودع.

بلا بريد عميلة تُستخدم خانة مستلم واحدة من حصة Google، ومع البريد خانتان. عند بقاء خانة واحدة تُعطى الأولوية لإشعار المالك. رسالة العميلة شكر ورقم طلب فقط؛ التفاصيل والمجموع في إشعار المالك. فشل الإرسال يظهر في لوحة الطلبات ولا يلغي طلبًا محفوظًا. توضح الحالة نجاح الإرسال للمتجر والعميلة، أو نجاح إشعار المتجر مع تعذر تأكيد العميلة. يدعم الجسر `action: "health"` دون إرسال، و`action: "test"` لإرسال اختبار إلى بريد المتجر فقط؛ كلاهما محمي بالسر.

حالة الربط الحالية: مُنحت صلاحية الإرسال لمشروع Google الخاص بالمتجر، ونجح تشغيل `initializeMailBridge` وإرسال اختبار فعلي إلى بريد المتجر. نُشر Web App بإعداد «الجميع» بعد موافقة المالك الصريحة، وتظل كل عملية إرسال مشروطة بالمفتاح. المفتاح محفوظ في Script Properties، والرابط والمفتاح في أسرار Worker. نجح فحص الاتصال من Worker وظهرت عبارة «بريد الطلبات متصل وجاهز للإرسال» في صفحة الإدارة.

يفحص `/api/mail-health` الربط برسالة `health` فقط، ويتحقق من هوية الخدمة وبريد المتجر وإتاحة حصة إرسال. يعيد مؤشرات حالة فقط دون أسرار أو تفاصيل العملاء. تُخزن النتيجة الناجحة في KV لخمس دقائق بمفتاح يتغير عند تغيير إعدادات البريد، وتُحد المحاولات الجديدة. اجتاز المتجر اختبارين فعليين: الدفع عند الاستلام دون بريد، وCliQ مع بريد المتجر لاختبار إشعاري المتجر والعميلة. تحققت الكميات والمجاميع ورسائل التأكيد، ثم أزيلت سجلات الاختبار وأعيدت كمياتها فقط إلى المخزون.
