## التشغيل والفحص

تعمل الاختبارات على Node.js 22 أو أحدث دون تنزيل تبعيات:

```bash
npm test
```

لمعاينة الواجهة ومحاكاة الطلب دون حفظ بيانات:

```bash
python3 -m http.server 8765 --directory public
```

افتح `http://localhost:8765`. تتطلب الإدارة Worker وD1 وKV. للتطوير الكامل في بيئة موثقة الصلاحية:

```bash
npm install
npx wrangler login
npm run db:local
npm run db:seed-local
npm run dev
```

ضع أسرار التطوير في `.dev.vars` المستبعد من المستودع. لا ترفع كلمات المرور أو رموز التفعيل.

## النشر الاعتيادي

يستخدم `wrangler.jsonc` إعداد Workers Assets للواجهة، وD1 للبيانات، وKV باسم `MEDIA` للصور المرفوعة. معرّفات الموارد تخص حساب المالك الحالي؛ أنشئ موارد أخرى وأبدل معرّفاتها إذا نقلت المشروع لحساب آخر.

للقاعدة الجديدة فقط:

```bash
npx wrangler d1 execute trend-shop-db --remote --file=db/schema.sql
npx wrangler d1 execute trend-shop-db --remote --file=db/seed.sql
```

لترقية قاعدة 1.2، طبّق `0002_product_details.sql` مرة واحدة قبل بيانات التشكيلة. **طُبقت هذه الترقية بالفعل على المعاينة الحالية؛ لا تكررها على القاعدة الحالية.**

يُبقي `seed.sql` الأسعار والمخزون والاعتماد الموجودة، لكنه يعيد الأسماء والأوصاف والصور وحالات العرض للتشكيلة الأصلية. لا تُعد تنفيذه بعد تعديل هذه الحقول من الإدارة دون مراجعة ونسخة احتياطية.

للنشر مع إبقاء `STORE_LIVE=false`:

```bash
npm run deploy
```

المعاينة الحالية تستخدم محول ملفات مضمّن يُبنى بواسطة `node scripts/prepare-api-preview.mjs`، والصور من KV. مخرجاته في `deployment-private/` المستبعد من التسليم. النشر الاعتيادي بـWrangler يخدم الصور المجمعة من `public/` مباشرة عبر Workers Assets، ويستخدم KV للصور الجديدة التي يرفعها المدير.

## الإدارة من الآيفون

افتح `/admin.html`. للتفعيل الأول أدخل الرمز الخاص الذي سُلّم للمالك واختر كلمة مرور من 14 حرفًا على الأقل. يُغلق التفعيل بعد إنشاء الحساب. لا يُحفظ نص كلمة المرور.

لتغيير صورة: افتح محرر المنتج، ثم «رفع صورة من الآيفون أو الجهاز»، واختر الصورة، وانتظر نجاح الرفع، ثم «حفظ التغييرات». يهيئ المتصفح الصورة إلى JPEG بأقصى ضلع 1600 بكسل، ويزيل بيانات EXIF. حد الخادم 1.5 MiB بعد التهيئة. إذا تعذر فتح صيغة من الجهاز، اختر نسخة JPEG أو PNG. يبقى إدخال رابط الصورة متاحًا.

الأوصاف والفوائد والاستخدام قابلة للتحرير من النموذج نفسه. الإخفاء والاستعادة يحفظان السجل وتاريخ الطلبات. صور العبوات مراجع بصرية؛ يُطابق الحجم والإصدار مع مخزون المورد قبل الاعتماد.

## الأسرار والبريد

`SESSION_SECRET` و`SETUP_TOKEN` موجودان كأسرار Worker؛ احتفظ بهما عند التحديث. يدعم الخادم تجزئة `ADMIN_PASSWORD_HASH` أو تجزئة المالك من D1 بعد التفعيل.

لربط البريد، ينشئ المالك مشروع Google Apps Script بحسابه، ويلصق `integrations/google-apps-script.gs`، ويضع سرًا عشوائيًا من 32 حرفًا أو أكثر في Script Properties باسم `TREND_WEBHOOK_TOKEN`. يُنشر Web App يعمل باسم المالك؛ كل طلب إليه يجب أن يحمل السر. يُحفظ رابط النشر في سر Worker `MAIL_WEBHOOK_URL` والسر المطابق في `MAIL_WEBHOOK_TOKEN`.

بلا بريد عميلة تُستخدم خانة مستلم واحدة من حصة Google، ومع البريد خانتان. رسالة العميلة شكر ورقم طلب فقط؛ التفاصيل والمجموع في إشعار المالك. فشل الإرسال يظهر في لوحة الطلبات ولا يلغي طلبًا محفوظًا.

## إعادة توليد الكتالوج

```bash
npm run catalog:curate
```

يقرأ `scripts/curate-catalog.py` الأصول والأوصاف والمصادر، ويولد الكتالوج وقرارات المراجعة وتحديثات SQL. مواد جمع الأدلة المؤقتة داخل `deployment-private/research/` غير مطلوبة لتشغيل المتجر. `prepare_catalog.py` و`build_offline_demo.py` من النسخة الأصلية؛ لا تستخدمهما لبناء الإصدار الحالي لأنهما يعيدان بيانات المعاينة القديمة.

اعتمد التشكيلة والأحجام والأسعار والخصومات والمخزون وصور الاستخدام، وحدد رسوم التوصيل والسياسات، وفعّل الإدارة واربط البريد واختبر طلبًا كاملًا على الآيفون. بعدها فقط يُغيّر `STORE_LIVE` صراحة إلى `true`. يرفض الخادم الطلبات إذا لم تكتمل إعدادات التشغيل. اختبار 100 عميلة في الحزمة محاكاة محلية للتزامن وليس اختبار حمل شبكيًا.
