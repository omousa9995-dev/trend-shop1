# Luma 5.19.10

The last live failure was classified as ACTION_FORMAT on the Interactions response before the bounded legacy alternate returned HTTP 503. This release normalizes single known function-call JSON objects as well as the flat action protocol. Lookup actions do not require customer-facing text; product actions can retain their declared carePlan field. Exact product IDs, including selection-only IDs, still pass through the same canonical stock, area, cart and budget validator.

The parser accepts complete JSON with an optional complete code fence, a single allowed action, or a single declared function-call object with object/JSON arguments. It rejects unknown actions, multiple-action arrays, invalid arguments and missing answer text. Syntax, object, action, argument and text failures use controlled category codes; raw provider text is never logged or returned as a diagnostic. No new public endpoint is added.
