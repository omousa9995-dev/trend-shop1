# Luma 5.19.5

The storefront offers Luma beside the header wordmark and through a prominent footer panel. Product, checkout and order routes hide these entry points and destroy any mounted chat, microphone, pending request and page lock. Product SSR strips the entries from its HTML. There is no floating Luma launcher or Korean-care navigation entry.

A microphone click starts recording subject only to the browser's native permission. Stopping or reaching 45 seconds automatically transcribes and submits exactly one message. Cancellation never submits; a separately typed draft survives. Audio files can also be attached and submitted automatically. Existing per-response device speech controls remain on demand. Conversations, recordings, photos and customer profiles are not saved in the store database; aggregate usage is recorded.

Chat uses bounded JSON actions from Gemini, dispatched through the existing server functions. The primary model is Gemini 3.5 Flash-Lite with one bounded alternate, Gemini 3.8 Flash. The model chooses a question, direct answer, live lookup, product cards or professional follow-up; the server validates that action. Initial turns contain no full-store inventory. Targeted small lookups include saved directions and ingredients; full details can be fetched by up to eight selected IDs. Empty lookups expose available product types so the model can refine its request. Up to five fact/reply rounds share a 65-second request deadline, with a 30-second per-provider-attempt deadline and a 70-second browser deadline. Retries remain bounded; long provider cooldowns and authentication/billing failures are respected.

Only canonical server product data determines card names, prices, stock, supported body area, delivery and confirmed purchase budget. Cards use the existing cart bridge; adding to cart remains a customer action. Advice covers everyday care and appropriate mild OTC concerns without inventing diagnoses, prescription regimens or guaranteed cures. Acute injury guidance works without inference. Personal follow-up uses the owner's confirmed Trend Shop pharmacists and existing WhatsApp destination.

No permanent key is sent to the browser. Diagnostic events expose only controlled model, transport, attempt and error categories. No raw provider error body or customer message is logged. Admin connection testing now performs a tiny real inference, subject to activation, throttling and the shared daily cap, rather than treating model metadata access as successful generation.

Validation: 462 local tests pass. Coverage includes server stock/price/budget checks, atomic daily caps, bounded attempts, multi-round lookups, safe malformed/incomplete responses, recording cancellation/automatic submission/draft preservation, page restoration and entry-point lifecycle. Cloudflare bindings, compatibility settings and live store data are preserved.

Production verification is recorded in docs/verification/luma-v519.json after deployment. Legacy native-tool/structured-schema attempts returned HTTP 503 during investigation. Real ordinary answers and a canonical PanOxyl 4% card/cart addition succeeded on the unconstrained JSON action path in 5.19.4; these observations do not imply upstream availability can be guaranteed. Native physical iPhone recording, acoustics and device speech must not be represented as hardware-tested by this cloud-browser run.
